# ذكرى · Thekra

منصة مراسلة عائلية بأرشفة ذكية: المحادثة هي الواجهة، والذاكرة هي المنتج.
المرجع التصميمي: `THIKRA_ذكرى.pdf` (تقرير الرؤية، أغسطس 2026).

> **للمطوّر الذي يستلم المشروع:** ابدأ من [docs/HANDOVER.md](docs/HANDOVER.md) (البنية، التشغيل، القرارات، وقائمة غير المكتمل بالأولوية).

## التشغيل

```bash
pnpm install
pnpm build        # يبني الواجهة إلى dist/
pnpm start        # http://localhost:8787  (الخادم + الواجهة)
pnpm test         # اختبارات المحرك والواجهة البرمجية
```

للتطوير مع إعادة التحميل: `pnpm dev:server` و`pnpm dev:web` (المنفذ 5173 مع وكيل إلى 8787).
القاعدة ملف SQLite في `data/thikra.db` (يستخدم `node:sqlite` المدمج في Node 24، بلا تثبيت إضافي).

أول مستخدم يسجّل يصبح **مشرف المنصة**. رمز OTP يُطبع في سجل الخادم ويظهر في الواجهة خارج بيئة الإنتاج فقط.

## ما هو منفّذ (المرحلة 1 من التقرير)

- تسجيل بالجوال + OTP، جلسات بكوكي HttpOnly، حد للمحاولات.
- دوائر بدعوة (رمز يراه رب الدائرة فقط)، أعضاء، مغادرة/إزالة.
- رسائل نصية وصوتية.
- **وكيل الأرشفة الحتمي** (`core/agent.ts`): تطبيع عربي، قاموس إشارات لثماني فئات، إشارات داعمة وعقوبات،
  درجة 0–100، عتبات الدائرة (صارم 70 / متوسط 42 / متساهل 26)، وحد أدنى مطلق 14 يرفض حتى مع الطلب اليدوي.
- وضع الدائرة اختياري، ويُنشر إشعار نظام لكل الأعضاء عند التفعيل/الإيقاف، ولا يُحلَّل أي شيء بأثر رجعي.
- أرشيف زمني قابل للبحث، ورب الدائرة يحذف أي عنصر (حكمه يعلو حكم الوكيل). كل حكم للوكيل معلّل ومرئي (شارة الرسالة).
- لوحة مشرف: أرقام وبيانات وصفية فقط، بلا محتوى رسائل.
- واجهة عربية RTL / إنجليزية LTR، PWA قابلة للتثبيت، حذف الحساب نهائياً.

## غير منفّذ بعد (حسب خارطة التقرير)

| المرحلة | البند |
|---|---|
| 2 | محادثات ثنائية ومجموعات عادية، تحويل مجموعة إلى دائرة، مزامنة جهات الاتصال |
| 3 | تفريغ صوتي على الخادم (حالياً تفريغ المتصفح إن توفر)، دمج الأحداث، استخراج التاريخ الفعلي، بطاقات الأشخاص، حلقة تعلّم العتبات |
| 4 | الذكريات السنوية، الرسائل المختومة (أقفال + تشفير)، الكتاب السنوي PDF |
| 5 | مزود SMS حقيقي، تطبيقات أصيلة |

نقاط الربط الجاهزة: SMS في `POST /api/auth/request`، نموذج لغوي (60/40) بجانب `assess()`، تفريغ صوتي في `POST /api/circles/:id/voice`.

## قبل الإنتاج

- ضع مزود SMS حقيقياً (الرمز الآن لا يُرسل لأحد).
- شغّل خلف HTTPS مع `NODE_ENV=production` (يفعّل كوكي Secure ويخفي رمز التجربة).
- أضف نسخاً احتياطياً لـ `data/` وتشفيراً للملفات الصوتية.

## البنية

- `core/`: النواة المشتركة (القواعد، البوابة، كاشف اللحظات، قارئ واتساب). كود TypeScript نقي يعمل على الخادم والمتصفح، وسيعمل على الجوال.
- `server/`: الواجهة البرمجية (Hono) وقاعدة البيانات والتخزين.
- `web/`: الواجهة (React).

## على Replit

1. في Replit: Create App ثم Import from GitHub، واختر مستودع ذكرى.
2. اضغط Run. الأمر الجاهز في `.replit` يثبّت ويبني ويشغّل على المنفذ 8787.
3. **لا تضع `NODE_ENV=production` للتجربة.** في وضع الإنتاج يختفي رمز التحقق الظاهر، ولا يوجد مزود SMS بعد، فلن يستطيع أحد الدخول.
4. للتجربة والعرض فقط. بيانات العائلة الحقيقية لا تُخزَّن على قرص Replit: عند الإطلاق نربط تخزيناً سحابياً وقاعدة بيانات خارجية (طبقة التخزين جاهزة لذلك).
5. يعمل على Node 20 أو أحدث. على Node 22.13+ يستعمل SQLite المدمجة، وعلى الأقدم (مثل Node 20 في Replit) يستعمل نسخة WebAssembly تلقائياً. ويمكن فرضها بـ `THIKRA_SQLITE=wasm`.

## اختبارات الخصائص
`pnpm test` يشغّل 150 سيناريو عشوائياً للثوابت I1–I5. عند الفشل يطبع البذرة؛ أعدها بـ `THIKRA_PROP_SEED=<n> pnpm test`، وللتعمق `THIKRA_PROP_RUNS=3000 pnpm test`.

`server/network.test.ts` يضيف شبكة سيئة (تأخير وقطع عشوائي) على خادم حقيقي. أعد بذرة بـ `THIKRA_NET_SEED=<n>` ولتطويل التشغيل `THIKRA_NET_MS=30000`.
