# هيكل المستودع (قرار F-08)

**الحالة:** قرار مسجَّل + خطوة تمكينية واحدة منجزة. **النقل الكامل مؤجَّل إلى ما بعد F-12.**

## القرار ولماذا
الهدف في [قائمة العمل](BACKLOG.md): `apps/mobile` و`packages/core` و`services/gateway` تُبنى وتُختبر معاً. **لا ننقل الملفات الآن**، لأن:
1. إطار تطبيق الجوال لم يُحسم (تجربة F-12 على جهاز أندرويد رخيص)، وتحديد شكل `apps/mobile` قبلها تخمين.
2. النقل الشامل يكسر كل `import` ويُربك سجل git بلا فائدة قبل وجود تطبيق ثانٍ يستهلك النواة.
3. ما يهم فعلاً اليوم أن **النواة مفصولة وقابلة للمشاركة**، وهي كذلك.

## الوضع الحالي والهدف
| اليوم | الهدف بعد F-12 | ملاحظة |
|---|---|---|
| `core/` | `packages/core` | TypeScript نقي بلا خادم ولا واجهة: المحرك، البوابة، اللحظات، استيراد واتساب، الهاتف، `Timeline`. **أصبح حزمة pnpm باسم `@thikra/core`** |
| `server/` | `services/gateway` | واجهة HTTP وبوابة WebSocket والتخزين |
| `web/` | `apps/web` | عميل الويب |
| — | `apps/mobile` | عميل الجوال، يستهلك `@thikra/core` |
| `bench/`، `brand/`، `docs/` | كما هي | |

## ما أُنجز الآن
- `core/package.json` بالاسم `@thikra/core` وحقل `exports` وتبعيته الوحيدة (`libphonenumber-js`)، وإدراج `core` في `pnpm-workspace.yaml`.
- الاستيراد النسبي الحالي (`../core/gate.ts`) يعمل كما هو، فلا شيء انكسر؛ والعميل الجديد يستورد `@thikra/core/...` حين يُبنى.
- يُتحقق منه بـ typecheck والاختبارات على نوعي SQLite وCI على Node 20 وNode 24.

## قاعدة ثابتة
`core/` **لا يستورد** من `server/` أو `web/` أبداً، ولا يستعمل واجهات المتصفح أو Node الخاصة. ما يحتاج ذلك يبقى خارجه. هذا ما يجعل الخادم والويب والجوال يشغّلون القواعد نفسها حرفياً.

## متى نعيد النظر
بعد نتيجة F-12: إن اخترنا React Native فـ`apps/mobile` ضمن المساحة نفسها؛ وإن اخترنا أصلياً (Swift/Kotlin) فالنواة تُستهلك عبر المحرك المشترك (Rust) كما في [الخطة الرئيسية](MASTER-PLAN.md)، وتُراجع هذه الوثيقة حينها.
